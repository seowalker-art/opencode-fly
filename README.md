# plugin_vscode-opencode_vpn — VSCode-плагин маршрутов opencode

Кнопки запуска opencode рядом с основной чёрной кнопкой (`sst-dev.opencode`
= «напрямую»):

| Маршрут | Кнопка | Вкладка | Базовый порт | Команда |
|---------|--------|---------|------|---------|
| VPN (хост → прокси 2082) | зелёная | `🛡 VPN` | 4098 | `opencode-console-vpn.sh` |
| Dock (контейнер) | синяя | `🐳 Dock` | 4100 | `opencode-console.sh` |
| VPS (Франция, будущее) | фиолетовая | `🖥 VPS` | 4099 | `opencode-vps.sh` (добавить) |

> **Порт — не лимит сессий.** В таблице указан **базовый** порт маршрута —
> его занимает первая сессия. Каждая следующая сессия («в новой вкладке»)
> получает **любой свободный порт** из диапазона 16384–65535 (проверка
> реальным bind, как в исходном плагине sst-dev.opencode). Ограничения в 3
> сессии нет: `VPN → 4098, затем 20473, 53821, …`.

## Структура

```
package.json         манифест расширения (идентификатор alex.opencode-vpn)
dist/extension.js    весь код плагина (ROUTES — маршруты данными, без правки кода)
images/              иконки кнопок (SVG) и иконка расширения (icon.png)
```

Маршруты задаются **данными** в `dist/extension.js` (массив `ROUTES`): id,
цвет/иконка, подпись вкладки, порт, команда запуска.

## Внешняя зависимость: проект vpn

Плагин **не содержит** скриптов запуска. Он ссылается на проект vpn
(`~/.config/vpn`) как на внешнюю зависимость:

- `scripts/opencode-console-vpn.sh` — opencode на хосте через VPN-шлюз
  (прокси из `config/vpn.yaml`), порт 4098;
- `scripts/opencode-console.sh` — opencode в контейнере (Dock), порт 4100.

Копировать скрипты сюда **нельзя**: они живут рядом со своим `config/vpn.yaml`,
`cfg.py`, `docker-compose*.yml` и `opencode-titled.sh`. При переносе/переименовании
vpn-проекта достаточно поправить константу `VPN_DIR` в `dist/extension.js`.

## Установка (копия в ~/.vscode/extensions)

Установленная копия — `~/.vscode/extensions/alex.opencode-vpn-0.0.2/`.
Обновление после правки исходника:

```bash
rsync -a --delete /path/to/opencode-fly/ \
  ~/.vscode/extensions/alex.opencode-vpn-0.0.2/
```

Затем в VSCode — **Developer: Reload Window**.

## Функции кода

- **Авто-перезапуск мёртвой сессии**: при клике на кнопку порт проверяется
  (`GET /app`), если сессия мертва — терминал закрывается и поднимается заново
  (фикс 20.08.2026).
- **Multi-session (фикс 20.08.2026)**: первая сессия маршрута занимает базовый
  порт (4098/4100); каждая следующая («в новой вкладке») получает **свободный
  порт** — как в исходном плагине sst-dev.opencode. Фиксированные порты ломали
  первое окно (второй `opencode --port 4098` не мог забиндить порт). Порт
  передаётся скриптам через `OPENCODE_CONSOLE_PORT` — vpn-проект не правится.
  Прокси для VPN всегда из `config/vpn.yaml` (2082) — API-порт opencode к
  маршруту трафика отношения не имеет, каждая сессия идёт через ВПН.
- **Прикрепление файла**: команда `opencode-vpn.addFilepathToTerminal`
  (`@файл`, с выделением `#L…` / `#L…-…`) — в терминал маршрута через
  `/tui/append-prompt`, либо текстом, если порт неизвестен.
- Окна различаются: цвет иконки вкладки + подпись в заголовке
  (`OPENCODE_TITLE_NAME`, эмодзи + метка).

## Замечания

- Плагин ставит `OPENCODE_TITLE=0` — opencode запускается напрямую (как
  sst-dev); различие окон — иконка + название. Ручной запуск скриптов из
  терминала — с обёрткой заголовка (`OPENCODE_TITLE=1`).
- Хост и контейнер — разные БД; хостовые маршруты (напрямую / VPN) делят одну
  хостовую БД. Каждый маршрут — свой exit-IP → своё окно квоты opencode.
